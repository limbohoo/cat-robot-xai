# The Colab tutorial, the XAI Fieldnotes site and the owner app: an analysis

The recognition program (`ml/catpose/`) reaches people through three outlets: a Colab tutorial for teammates and teachers, a public site for learning XAI, and an app for cat owners. All three describe the same pipeline, for different readers and with different standards of evidence. This document covers what each one does, which section of the paper it supports, and how far it can be trusted.

## Overview

| | Colab theory tutorial | XAI Fieldnotes site | Owner app |
| --- | --- | --- | --- |
| Reader | Teammates, course teachers | Industrial-design and HCI learners (public) | Cat owners |
| Question it answers | What is the maths of each step, and how strong is the evidence | Which XAI methods exist, and how does this system reach a judgement step by step | How was my cat today, why does the app say so, what should I do |
| Data | Public dataset samples, events from a web video, synthetic data | Keypoints and numbers from a web video (no frames) | 46 real moments of the silver cat from the 16 October test |
| Link to the program | Section 6.14 imports the program's rule files | `/case` ports the rules line by line to TypeScript | Report generated by `report_ui.py`; the web prototype uses the same report data |
| Paper sections | 2.2, 3.2.1, 3.3.1 | 2.1.1, appendix | 2.1.1, 3.1.2, 3.2 App |
| Location | `ml/colab/` | https://xai-fieldnotes.vercel.app | Figma page "V3 - ready to test"; web prototype Cat Feeling Beta |

## 1. Colab theory tutorial (`ml/colab/CatPose_XAI_Tutorial.ipynb`)

**What it does.** 78 cells in 11 chapters, from detection to the report: detection, keypoints, temporal smoothing, geometric features, state inference, explainability, robot-interaction theory, a reinforcement-learning simulation, data and deployment, version history and limitations, references. Every section carries an evidence grade: ✅ run on the real model or real video, 🧪 prototype or synthetic data, 📐 theory only. The notebook is generated by `build_notebook.py` and needs the data pack `catpose_colab_pack.zip` (about 40 MB: dataset samples, weights and event data) in a Google Drive folder named `CatPose-XAI`. A practical notebook, `CatPose_Run.ipynb`, takes a video and returns the same owner report as the desktop program.

**Strongest parts.**
- The key design decision is stated up front: no end-to-end "image to emotion" network. Human-readable keypoints and geometric features sit in between (a concept bottleneck), because there are no emotion labels while keypoint datasets are public.
- Section 4.7 measures, for each feature, the ratio of model error to between-cat variation. That ratio decides which features may trigger a label on their own, so this part of the rule thresholds is backed by measurement.
- Section 6.14 imports the program's own rule files and runs counterfactual checks on real events (7/7 pass). It also shows that a card citing the wrong evidence is caught. This tests the deployed system, not a demo model.
- Section 10.1 lists each fixed problem with how it was found, what changed and the before/after numbers; section 10.5 states four criticisms of the project and the responses.

**Limitations.**
- The emotion layer (5.3–5.12) is demonstrated on synthetic data with hand-set probabilities.
- The Shapley values, contrastive explanations and deletion tests in chapter 6 run on a synthetic tabular model, not on the deployed system. Occlusion sensitivity was run on one image and one keypoint only, as a sanity check.
- The robot POMDP and Thompson sampling in chapters 7–8 are simulations with assumed parameters for the simulated cat.
- The data pack contains CatFLW images (CC BY-NC), so it is not in this repository and has to be shared separately.

## 2. XAI Fieldnotes site (https://xai-fieldnotes.vercel.app)

**What it does.** A bilingual Next.js site deployed on Vercel; source in `limbohoo/xai_fieldnote`.

| Page | Contents |
| --- | --- |
| Home learning guide | Five collapsible chapters: field and questions; six methods (interpretable models, TreeInterpreter, SHAP/TreeSHAP, LIME, Grad-CAM, counterfactuals) with paper cases; a method atlas; a ten-step workflow and evaluation; further reading. Six reflection-note boxes, stored only in the browser |
| `/glossary` | 138 bilingual terms in eight topics, with sources |
| `/case` case lab | Takes one 36-second web video of a cat apart step by step: find the cat, measure features, compare with itself, apply rules, guess, check the explanation, then build the owner report and a phone prototype. Every step is hands-on |
| `/model` 3D walkthrough | A three.js stack of the nine pipeline stages; click any layer for its formula, dimensions, parameters and a hands-on view. Each stage says where its numbers come from: off-the-shelf model, network we trained, formula, or hand-set |

**Agreement with the program.** The `/case` rules are a line-by-line TypeScript port of the Python program (`app/case/core.ts`). 1065 of 1066 frames match the program's own labels, and all 7 event checks pass. The video is embedded from YouTube; the site publishes only keypoints and numbers, never frames.

**Strongest parts.** `/model` shows on every layer which numbers are learned and which are hand-set, so a reader sees at once that learning happens only in the first two steps. `/case` lets readers drag a threshold and watch the label change, which shows why a rule-based system is explainable more directly than prose can.

**Limitations.**
- The case uses a web video, not the team's own test recording.
- There has been no user test, so there is no evidence that readers understand it.
- The site README records that lint could not run (the configured rule is missing from the current oxlint) and that the site was checked in one browser and at a 375 px width only.

## 3. Owner app

The app exists at three levels of maturity.

| Form | State | Data |
| --- | --- | --- |
| `report.html` generated by `catpose` | Working; produced automatically after a test | Real: events, clips, before/after frames, evidence, guess, confidence |
| Web prototype Cat Feeling Beta | Clickable, six screens | 46 real moments of the silver cat; robot runs are mock data |
| Figma design "V3 - ready to test" | Design; prototype links not finished | Matches the web prototype |

**What it does.** Six screens: Home (the day's timeline, at most 5 moment cards, an ⓘ explaining that feelings are the AI's visual guesses); All moments (filters; clusters within 90 s fold after 3); One moment (before/after frames, evidence, the other possibility, a sticky "Yes / No / Not sure" bar; "No" opens "What was it"); Suggestions (Tips and System tabs; Tips covers play only); Robot (pick a game, run history); Playing now (a two-minute simulated timer with speed, pause and stop).

**Design rules.** A warm tone written for owners ("Wanted to play", "Seemed tense", "Did we read it right?"); theme colour #61CDAB; times to the minute only; each fact once per screen; every tap target at least 44 px and text contrast at least 4.5:1.

**Relation to XAI.** The app is the presentation layer of the three-layer explanation in paper section 2.1.1. Cards show the evidence with circled points; the other possibility and how to tell them apart express uncertainty; low-confidence moments are hidden; the owner's answers are designed as a label source.

**Limitations.**
- Owner answers live only in the browser and are not wired to the program's `learn()` that updates the priors.
- Robot runs on the robot screen are mock data. The real robot was driven by a teammate, and the app cannot control it.
- No owner usability test was done.
- The web prototype is a private claude.ai page and the Figma file is password-protected, so reviewers need access granted separately.

## 4. What the three show together

All three outlets use the same rules and data, and each one checks its agreement with the program: the Colab imports the rule files, the site compares labels frame by frame, and the app uses the report data the program generates. So the claim "the explanation states the system's real evidence" holds in all three places.

They also share the same gap. The emotion layer has no human labels, and nobody has tested whether readers understand the explanations or trust the system more appropriately because of them. Together they show that the system is transparent. They do not show that its judgements are correct.
