# Colab 教程、XAI Fieldnotes 网站与主人 App：分析

本项目的同一套识别程序（`ml/catpose/`）有三个出口：给组员和老师读的 Colab 教程，给公众学习 XAI 的网站，给猫主人用的 App。三者讲的是同一条流水线，读者和证据要求各不相同。本文逐个说明它们做了什么、对应论文哪一节、可靠到什么程度。

## 总览

| | Colab 理论教程 | XAI Fieldnotes 网站 | 主人 App |
| --- | --- | --- | --- |
| 读者 | 组员、课程老师 | 工业设计与 HCI 学习者，公开 | 猫主人 |
| 回答的问题 | 每一步的数学是什么，证据到哪一级 | XAI 方法有哪些，这套系统怎样一步步做判断 | 今天猫怎么样，凭什么这么说，我该做什么 |
| 数据 | 公开数据集样本，网络视频的事件，合成数据 | 网络视频的关键点和数值（不含画面） | 10 月 16 日实测中银猫的 46 个时刻 |
| 与程序的关系 | 6.14 直接导入程序的规则文件 | `/case` 用 TypeScript 逐行移植规则 | 报告由 `report_ui.py` 生成；网页原型用同一份报告数据 |
| 论文对应 | 2.2、3.2.1、3.3.1 | 2.1.1、附录 | 2.1.1、3.1.2、3.2 App |
| 位置 | `ml/colab/` | https://xai-fieldnotes.vercel.app | Figma 页面 “V3 - ready to test”；网页原型 Cat Feeling Beta |

## 1. Colab 理论教程（`ml/colab/CatPose_XAI_Tutorial.ipynb`）

**它做什么。** 78 个单元，从检测一路讲到报告，共 11 章：检测、关键点、时序平滑、几何特征、状态推断、可解释性、机器人交互理论、强化学习模拟、数据与部署、版本披露与局限、参考文献。每一节标出证据等级：✅ 在真实模型或真实视频上运行过，🧪 原型或合成数据，📐 只有理论。笔记本由 `build_notebook.py` 生成，需要把数据包 `catpose_colab_pack.zip`（约 40 MB，含数据集样本、权重和事件数据）放到 Google Drive 的 `CatPose-XAI` 文件夹。另有一个实用版 `CatPose_Run.ipynb`，输入一段视频，输出和电脑上相同的主人报告。

**最有价值的部分。**
- 关键的设计决定写在开头：不训练“图像到情绪”的端到端网络，中间插入人能看懂的关键点和几何特征（concept bottleneck）。理由是没有情绪标签，而关键点有公开数据。
- 4.7 节测出每个特征的模型误差和猫间差异之比，直接决定了哪个特征能单独触发标签。这是规则阈值有据可查的部分。
- 6.14 节把程序本身的规则文件导入笔记本，在真实事件上做反事实检验（7/7 通过），还演示了写错依据的卡片会被查出来。这一节检验的是部署的系统，不是演示模型。
- 10.1 节列出每个已修复问题怎么发现、改了什么、改前改后的数字；10.5 节写了四条对项目的批评和回应。

**局限。**
- 情绪层（5.3–5.12）用合成数据演示，概率是手设的。
- 第 6 节的 Shapley、对比解释、删除测试都在合成的表格模型上运行，不在部署系统上；遮挡敏感度只在 1 张图、1 个关键点上做过，是健全性检查。
- 第 7–8 节的机器人 POMDP 和 Thompson sampling 是模拟，模拟猫的参数全部是假设。
- 数据包含 CatFLW 图片（CC BY-NC），不放进本仓库，需要单独分发。

## 2. XAI Fieldnotes 网站（https://xai-fieldnotes.vercel.app）

**它做什么。** Next.js 网站，部署在 Vercel，中英双语，源码在 `limbohoo/xai_fieldnote`。

| 页面 | 内容 |
| --- | --- |
| 首页学习指南 | 五个可折叠章节：领域与问题；六种方法（可解释模型、TreeInterpreter、SHAP/TreeSHAP、LIME、Grad-CAM、反事实）与论文案例；方法图集；十步工作流与评估；延伸阅读。六个反思笔记框，内容只存在浏览器本地 |
| `/glossary` | 138 条双语术语，八个主题，附来源 |
| `/case` 案例实验室 | 用一段 36 秒的网络猫视频，一步步拆开系统：找猫、量特征、和自己比、套规则、推测、检验解释，最后生成主人报告和手机原型。每一步都能动手改 |
| `/model` 3D 图解 | three.js 把九个步骤排成一摞 3D 实体，点任何一层看公式、维度、参数和动手视图；每一步标明参数来源：现成模型、我们训练的网络、公式或手设数字 |

**和程序的一致性。** `/case` 的规则是 Python 程序的逐行 TypeScript 移植（`app/case/core.ts`），1066 帧里有 1065 帧与程序自己的标签一致，7 个事件的忠实度检验全部通过。视频从 YouTube 嵌入，网站只发布关键点和数值，不带视频画面。

**最有价值的部分。** `/model` 把“哪些数字是学出来的、哪些是手设的”放在每一层上，读者一眼能看出这个系统的学习只发生在前两步。`/case` 让读者自己拖动阈值、看标签怎么变，比文字更直接地说明规则式系统为什么可解释。

**局限。**
- 案例用的是网络视频，不是本组的实测录像。
- 没有用户测试，读者是否真的读懂没有证据。
- README 记录：lint 规则与当前 oxlint 版本不兼容，没跑；只在一种浏览器和 375 px 宽度下检查过。

## 3. 主人 App

App 有三个层次的实现，成熟度不同。

| 形态 | 状态 | 数据 |
| --- | --- | --- |
| `catpose` 生成的 `report.html` | 可用，测试后自动生成 | 真实：事件、片段、前后帧、依据、推测、把握 |
| 网页原型 Cat Feeling Beta | 可点击，六个页面 | 银猫的 46 个真实时刻；机器人记录是模拟数据 |
| Figma 设计 “V3 - ready to test” | 设计稿，原型连线未完成 | 与网页原型对应 |

**它做什么。** 六个页面：首页（一天的时间线，最多 5 张时刻卡片，一个 ⓘ 说明“情绪是 AI 的视觉推测”）；全部时刻（筛选，90 秒内的聚类超过 3 个时折叠）；单个时刻（前后两帧、依据、另一种可能、底部固定的“对 / 不对 / 说不准”，选“不对”会弹出“那是什么”）；建议（Tips 与 System 两个标签，Tips 只讲玩耍）；机器人（选择游戏、运行记录）；正在玩（两分钟模拟计时，可调速、暂停、停止）。

**设计规则。** 语气温和、写给主人（“想玩了”“好像紧张”“我们读对了吗？”）；主题色 #61CDAB；时间只精确到分钟；同一屏每个事实只出现一次；所有点击区至少 44 px，文字对比度至少 4.5:1。

**和 XAI 的关系。** App 是 2.1.1 节三层解释里的呈现层：卡片给出依据和红圈，另一种可能和分辨方法表达不确定，把握低的时刻不展示，主人的回答设计为标签来源。

**局限。**
- 主人的回答只存在浏览器本地，没有接到程序里更新先验的 `learn()`。
- 机器人页面的运行记录是模拟数据；机器人实际动作由组员遥控，App 不能控制机器人。
- 没有做主人使用测试。
- 网页原型是私有的 claude.ai 页面，Figma 文件有密码，评审需要单独授权。

## 4. 三者合起来说明了什么

三个出口共用同一份规则和数据，并且各自检验过一致性：Colab 直接导入规则文件，网站逐帧对照程序标签，App 用程序生成的报告数据。这使得“解释写的就是系统真正的依据”这句话在三个地方都成立。

三者共同的缺口也一样：情绪层没有人工标注，读者是否读懂、是否因此更合理地信任系统，都没有测过。它们能证明系统透明，不能证明系统判断得对。
