# 反应识别与事件报告：原理、用法与局限

这份文档说明 v3 新增的三个模块：`catpose/features.py`（几何特征）、`catpose/reactions.py`（行为反应分类）和 `catpose/events.py`（状态变化事件与报告）。每一步的数学推导和可运行的验证，见 Colab 教程第 4–6 节。

## 1. 整体流程

```
摄像头 / 视频
  → YOLO 找到猫
  → 身体 20 点 + 脸部 48 点（One-Euro 平滑）
  → 几何特征 f（每帧）
  → 与这只猫的基线比较，得到 z 值
  → 头部姿态门控：视角不正时，暂停脸部特征
  → 行为反应规则（防抖：连续 10 帧才切换）
  → 状态变化事件 → HTML 报告
```

## 2. 几何特征

记左右眼中心为 $e_L, e_R$，眼间距 $d$ 作为长度单位。“向上”的方向垂直于眼线、背离下巴。所有特征对尺度、平移和画面内的旋转不变。

| 特征 | 含义 | 依据（关键点编号见 Colab 4.2） | 可靠度* |
|---|---|---|---|
| `ear_height` 耳尖高度 | 耳尖在眼线之上多高，单位是眼间距 | 耳尖 24、29 | **0.15，可靠** |
| `ear_angle` 耳外展角 | 耳轴偏离“向上”方向多少度，向外为正 | 耳朵轮廓 22–31 | 0.54，只作补充 |
| `eye_aperture` 眼睛开合度 | 眼睛高度 / 宽度 | 眼周 4–11 | 0.41，只作补充 |
| `muzzle_ratio` 口鼻比 | 两侧胡须垫的距离 / 眼间距 | 32、35 | 0.52，只作补充 |
| `head_drop` 头部下垂 | 鼻子比肩胛低多少，单位是体长 | 身体点 | 未测；只适用于站立或坐着的猫 |
| `activity` 活动量 | 身体关键点速度的中位数，单位是“每秒几个猫身长”，上限 3 | 身体点 | 未测 |

\* 可靠度 = 模型误差 / 猫与猫之间的真实差异，在 12 张验证脸上测得（Colab 4.7）。越小越好，低于 0.3 才能单独作为证据。

**为什么 CatFLW 的编号要我们自己确定？** 数据集没有公布 48 个点各自的名字。我们用训练集的平均脸形和左右对称关系确定了编号，可以在 Colab 4.3 的图上核对。

## 3. 个体基线

每只猫的耳朵、眼睛形状都不同（例如折耳猫的耳朵天生就低），所以每个特征都和**这只猫自己的平常状态**比较：

$$z = \frac{f - \text{中位数}}{\max(1.4826 \cdot \text{MAD},\ \text{模型测量误差})}$$

- 基线来自看到猫之后的前 `--calib-frames` 帧（默认 300）。**校准时猫应该是安静的**。按 `b` 可以重新校准。
- 分母的下限是**模型测量误差**。没有这个下限，校准时猫几乎不动，MAD 会极小，任何一点抖动都会被放大成几十个 SD。这曾在真实视频上造成 40% 的误报。
- 用 `--baseline-out cat.json` 保存基线，下次用 `--baseline-in cat.json` 加载。

## 4. 头部姿态门控

特征只对**画面内**的旋转不变。猫抬头、低头或转头时，脸在画面上被压缩，耳朵看起来“变低”了，其实耳朵没动。所以：

- **偏转（yaw）**：左右眼到鼻子的距离不对称程度超过 0.2 → 暂停脸部特征。
- **俯仰（pitch）**：鼻子到眼线的距离 / 眼间距，和基线相比变化超过 30% → 暂停脸部特征。

**已知不足**：模拟实验显示，门控要到抬头约 45° 才启动，而 20° 时耳尖高度就已经低了 3 个 SD 以上。Colab 4.12 给出了一种俯仰修正方法，但还没有在真实片段上验证，所以代码里还没有采用。

## 5. 行为反应规则

| 标签 | 条件（z 值） |
|---|---|
| `no clear change` 没有明显变化 | 都在基线范围内；或者脸被暂停，而身体没有明显活动 |
| `active` 活跃 / 探索 | 活动量 ≥ +2 |
| `alert` 警觉 / 定向 | 耳尖高度 ≥ +1.5，且不在剧烈运动；眼睛睁大（≥ +2）只作补充证据 |
| `ears back` 耳朵后压 / 外转 | 耳尖高度 ≤ −1.5；或者耳外展角 ≥ +2 **并且**耳尖高度 ≤ −0.5 |
| `freeze` 僵住 | 耳朵后压，同时活动量 ≤ −1 |
| `unknown` 看不清 | 没有可信的关键点 |

两条原则：**只有可靠的特征才能单独触发标签**；**新标签要在最近 0.3 秒内占多数（≥ 60%）才显示**（`--reaction-hold`）。按时间而不是帧数计算，所以在慢电脑上延迟也一样；用“占多数”而不是“连续 N 帧”，标签在两个相邻状态之间来回跳时也能切换。实时显示约有 0.2 秒延迟。

这些规则的方向来自 Feline Grimace Scale 的耳朵动作单元（Evangelista et al. 2019）和面向主人的身体语言指南（Cats Protection），**具体数值是猜测**，需要用标注数据来调整。注意：Bennett et al. (2017) 发现和恐惧、挫败最相关的面部动作主要是眨眼、嘴部动作和头部转向，而不是耳朵，这些目前都没有测量。

## 6. 事件报告

猫从“没有明显变化”进入其他反应时，就记为一个事件；回到“没有明显变化”时事件结束，并记录持续时间。实时标签反应很快，所以报告**只收录持续 0.5 秒以上的变化**，更短的只在开头注明次数。每个事件回答两个问题：

**它身上变了什么？** 比较“变化被确认的那一刻”和“变化前 1–2.5 秒”的 z 值，只列出变化 ≥ 1 SD 的特征，并在“变化后”的图上圈出对应部位。和几秒前的自己比，天然避开了品种和个体差异。

**变化之前发生了什么？** 检查变化前 3 秒内：
- 声音突然变大（比之前 5 秒的中位数高 10 dB 以上；需要 ffmpeg，只对视频文件有效）；
- 猫以外的画面区域出现明显运动（超过平时的 3 倍）；
- 以后可以接入机器人的动作记录。

**线索可信吗？** 报告开头会把每种线索在“事件前 3 秒”出现的比例，和“任意 3 秒窗口”里出现的比例（基准）相比，得到**提升度（lift）**。lift ≈ 1 表示和事件无关，报告会明确写“不能当作线索”。例如样例视频全程有配乐，声音的 lift 是 1.0。

## 7. 输出文件

`--report-dir` 文件夹里：
- `report.html`：报告，图片已嵌入，可以单独转发；
- `events.json`：所有事件的结构化数据；
- `img/`：每个事件的前后对比图。

`--features-csv` 的列：`time, frame`，每个特征的数值和 `_z`，以及 `reaction`。

## 8. 帮忙打标签：我们的第一批真实数据

1. 用自己的猫或视频生成报告。
2. 复制下面的表格，**两个人各自独立**填写，不要互相看：

| 事件时间 | 系统标签 | 标签对吗（对 / 错 / 看不清） | 如果错，应该是什么 | 备注（例如猫在做什么、画面有什么问题） |
|---|---|---|---|---|
| 00:17.8 | freeze | | | |

3. 判断时只看**可见的形态**：耳朵真的放低了吗？猫真的静止了吗？**不要**判断情绪。
4. 汇总后计算两人的一致性（Cohen's κ）。一致性高的部分就可以用来检验和调整规则阈值。

## 9. 局限

- 反应标签没有经过人工标注验证。
- 猫贴近镜头时，身体关键点不稳，活动量会异常。
- 头部姿态门控只能拦住大角度的转头和抬头。
- 头部下垂和活动量的测量误差下限是经验值。
- 只支持画面里有一只猫。
- 缺少尾巴、胡须、瞳孔和叫声。

## 10. 推测的情绪，以及它怎样随后续行为更新（`catpose/interpret.py`）

报告里每个事件最显眼的是“看起来像：X（推测 · 把握高/中）”。它**不是情绪识别**，而是一个会随猫随后的行为更新的推测：

1. **起点**：根据行为标签给一个初始分布（例如“耳朵后压”：紧张 40%、专注地听 30%……）。数值来自文献方向，是手写的假设。
2. **随后 5 秒的线索**逐个更新它（朴素贝叶斯）：随后离开或躲开、随后靠近、随后扑玩（持续 0.5 秒以上）、随后很快平静、随后保持不动、之前小车刚有动作。
3. **把握程度**：最高的可能 ≥ 60% 且领先第二名 30% 以上为“高”；≥ 45% 且领先 15% 以上为“中”；否则为“低”，**低时不显示推测**，只描述行为。依赖脸部的标签在脸看不清时一律为“低”。
4. 报告里可以展开“为什么这么推测”，看到每一步线索怎样改变推测；同时附上**视频片段**（`clips/` 文件夹），主人可以自己判断。

## 11. 测试当天怎么运行

```bash
.venv/bin/python -m catpose.realtime --source 0 --detect --calib-frames 300 \
    --report-dir reports/test1 --robot-log reports/test1/robot.csv
```

- `--robot-log`：小车动作记录，CSV 两列 `time_s,action`（从录像开始算起的秒数）。报告会据此列出“小车每次互动后猫的反应”，并把“之前小车刚有动作”作为线索。
- 报告是一个**文件夹**（`report.html` + `clips/`），转发时请把整个文件夹打包。

## 12. 测试之后：用标注更新推测规则

1. 报告文件夹里有 `labels_template.csv`，每个事件一行。组员看视频片段，在 `your_label` 一列填写：`tense` / `curious` / `playful` / `attentive` / `calm`，拿不准就填 `unsure`。
2. 运行：

```bash
.venv/bin/python -m catpose.interpret --events reports/test1/events.json \
    --labels reports/test1/labels_template.csv --out interp_v2.json
```

3. 以后用 `--interp-config interp_v2.json` 运行，就会使用更新后的规则。

更新方式是在手写的初始值上**累加计数**（每个初始值相当于 10 个样本），所以几条标签只会轻微地调整规则，不会被个别样本推翻。标签越多，规则越接近你们这只猫的实际情况。**注意**：同一批事件既用来更新规则、又用来评价规则，会高估准确率；评价要用另一次测试的数据。

## 13. 给主人看的报告界面（`catpose/report_ui.py`）

报告按“主人回家后 1 分钟看懂”设计，分三层：
1. **总览**：一句话总结、时间占比条、小车每次邀请后的反应；
2. **值得看的时刻**：每个时刻一张卡片（缩略图 + “看起来像 X” + 把握程度）。把握低的时刻收进“另有 N 个时刻看不太清”；
3. **点开卡片**：先看视频，再看“也可能是”和“怎么分辨”；然后是“**为什么标为「X」**”（判断真正依据的特征，分主要依据和补充，并写出“如果……回到平时，就不会标为 X”），可以展开“为什么这么推测”，最后是前后对比和“和 2 秒前相比”的变化。详见第 16 节。

每个时刻都有“这个推测对吗？对 / 不对 / 说不准”和补充说明。答案保存在浏览器里，点底部的“**导出我的反馈（CSV）**”就能得到用户测试的数据。SD、lift、推测分布等技术数字都折叠在最底部的“技术细节（给研究者）”里。

## 14. 一次测试 = 一个会话文件夹（`catpose/session.py`）

把同一次测试的所有视频和小车日志放进一个文件夹，一条命令生成一份合并的报告：

```bash
.venv/bin/python -m catpose.session sessions/test1 --init      # 第一次：生成 session.json 和 robot_log.csv 模板
.venv/bin/python -m catpose.session sessions/test1 --dry-run   # 先只检查时间对齐（写出 sync.json）
.venv/bin/python -m catpose.session sessions/test1             # 分析全部视频，输出 sessions/test1/report/
```

**时间怎么对齐：**
1. 每段视频的开始时间：优先用 session.json 里的 `start`（钟点时间）或 `offset`（秒），否则用视频文件里的录制时间；
2. 再用**声音**自动校准：同一个房间里的摄像头会录到同样的声音（门响、说话、小车的声音），程序比对声音找出精确的时间差，并给出相关系数。系数低于 0.3 就不采用，并在报告里提示；
3. 小车日志的时间可以是钟点时间（`2026-10-20T14:15:00`）、Unix 时间戳，或从会话开始算起的秒数。名字里带 `stop` 的事件记为安全停止。

**多个视角怎么合并：** 不同摄像头在 2 秒内拍到的同一时刻合并为一个，看得更清楚的视角在前，另一个作为“换个角度看”。**两个视角的推测不一致时，不会悄悄选一个**：卡片上会注明“另一个视角看起来更像……”，并把把握降低一级。

**输出：** `report.html` + `clips/`（给主人看）、`labels_template.csv`（组员标注）、`events.json`（用标注更新规则）、`timeline.csv`（视频事件和小车事件排在同一条时间线上）、`sync.json`（每段视频的时间来源）。

## 15. 预先想到的情况，以及程序会怎样提示

| 情况 | 程序怎么做 | 测试时怎么避免 |
|---|---|---|
| 很长时间拍不到猫 | 拍到猫的时间少于 50% 时，在报告顶部提示 | 摄像头对准猫常待的地方；可以多放一台 |
| 两个视角推测不一致 | 注明不一致，把握降一级 | 正常现象，主人可以两个视角都看 |
| 小车动作时没有摄像头在录 | 报告顶部提示，这一轮显示“不在画面里” | 先开所有摄像头，最后才启动小车 |
| 校准期间小车已经在动 | 报告顶部提示：基线可能不准 | 小车启动前，先让猫安静地被拍 5 分钟 |
| 某段视频无法确定开始时间 | 报告顶部提示，要求手动填写 | 所有设备开始录像时**拍一下手**（或让小车发出一声提示音），声音对齐就有了依据 |
| 声音对齐不可靠（没声音或很安静） | 不采用，按文件时间，并提示可能有几秒误差 | 同上；或者在 session.json 里填写 offset |
| 设备时钟不准 | 声音对齐会修正开头的误差 | 测试前把手机、电脑、小车的时间对一下 |
| 家里不止一只猫 | **目前只跟踪画面中最明显的一只** | 测试时让其他猫待在别的房间 |
| 光线太暗 | 检测会漏，表现为“拍不到猫”的比例升高 | 测试时开灯，或选白天 |

## 16. 解释说的是不是真正的依据（`catpose/faithfulness.py`）

课程的第二层检验要求：系统说它依据的，必须就是它实际依据的。我们的标签和推测都来自透明的规则，所以可以**精确地**检验，不需要近似。

**之前的问题。** 旧版卡片只列“和 2 秒前相比”变了什么，而标签是按“和它平时比”的偏离决定的，两者不是一回事。实际出现过：卡片标题写“耳朵压低”，依据里却只有“身体静下来了”。在测试视频的 7 个事件里，有 3 个事件的旧卡片没有写出主要依据。

**现在怎么做。**
1. 每个标签都记下触发它的条件：哪个特征、偏离了多少、越过了哪个阈值（`Reaction.drivers`）；
2. 标签切换时，记下这次判断用到的数值：投票给新标签的那几帧的中位数（`Event.z`），以及之前的标签（决定用的是进入还是退出阈值）；
3. 卡片上的“为什么标为「X」”就从这里生成，画面上的红圈也只圈判断依据的部位。

**每个事件自动做五项检验：**

| 检验 | 做法 | 通过的意思 |
|---|---|---|
| 能重现 | 用记录下来的数值重跑规则 | 得到同样的标签 |
| 写出的就是原因 | 把卡片写出的特征改回它平时的值（z = 0） | 标签改变；单独改回就会改变的叫“主要依据”，否则是“补充” |
| 没有隐藏的原因 | 把卡片**没写**的特征全部改回平时的值 | 标签不变 |
| 推测能重现 | 用同样的后续线索重算推测 | 得到同样的推测和把握 |
| 哪一步是关键 | 逐条去掉后续线索 | 去掉后推测或把握改变的线索，卡片上写成“关键的一步：……如果没有这一步，……” |

前四项都通过，这个事件才算通过。卡片底部会写“已自动检验……”；没通过时会如实写出哪一项没通过。

**结果。** 测试视频：7 个事件全部通过；两路视频的模拟测试：8 个事件全部通过。单元测试 `tests/test_explanations.py` 里还专门放了一个“写错依据”的例子，检验能把它查出来。

**它不能说明什么。** 这些检验只说明解释忠实于规则，不说明规则对猫的判断是对的。后者要靠人工标注来检验（课程的第一层）。

```bash
.venv/bin/python -m catpose.faithfulness reports/我的视频     # 对已有报告重新检验并逐条列出
```
